Phase 5 Design Doc: System Hardening & IntelligenceGoal: Implement advanced security protocols, data aggregation logic, and administrative oversight.1. Advanced Identity: Refresh Token RotationTo prevent unauthorized access if a JWT is intercepted, we move to a dual-token system.Mechanism: * Access Token: Short-lived (15 mins), stored in memory.Refresh Token: Long-lived (7 days), stored in a HttpOnly cookie.Rotation: Every time the Access Token expires, the user sends the Refresh Token. The backend issues a new pair and invalidates the old ones. If an old Refresh Token is reused, the system detects a breach and logs out all sessions.2. The Health Timeline Aggregator (Intelligence)Instead of the frontend making separate calls for records, notes, and appointments, the backend will "stitch" them together.Database Strategy: Use the MongoDB Aggregation Pipeline.The $facet Operator: This allows the backend to process three independent queries (Records, Appointments, Notes) in a single database pass and combine them into one array.Result: A unified JSON feed where every event has a type and a date, allowing the frontend to render a vertical "Facebook-style" timeline of a patient's health journey.3. Two-Factor Authentication (2FA) SimulationAdding the final layer of defense for healthcare data.Workflow:User enters password.Backend checks is2FAEnabled. If true, it generates a 6-digit OTP and stores the hash in an OTPTokens collection.Backend returns a 2FA_REQUIRED status.User submits OTP; backend verifies and only then issues the final JWT.4.
