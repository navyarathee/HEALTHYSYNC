Backend Architecture Design: Phase 21. New Data Models (Schema Design)To support consent and auditing, we need three new collections in MongoDB.Consent Collection:id, patientId, providerId, accessLevel (ALL_RECORDS, SPECIFIC_CATEGORY), status (ACTIVE, EXPIRED, REVOKED), expiresAt (TTL Index).AuditLog Collection:id, userId, action (LOGIN, RECORD_VIEW, CONSENT_GRANT), resourceId, accessReason (Enum: TREATMENT, EMERGENCY, etc.), ipAddress, timestamp.TwoFactorAuth Collection:userId, otpHash, expiresAt, attempts.2. The Consent Engine (Middleware Logic)The core security feature is a Consent Middleware that intercepts requests to view patient data.Logic Flow: 1.  Intersects the request containing patientId.2.  Checks if req.user.role === 'PATIENT' and matches the patientId (Self-access).3.  If req.user.role === 'PROVIDER', it queries the Consent Collection for an active record where providerId === req.user.id and status === 'ACTIVE'.4.  If no active consent exists, returns 403 Forbidden.3. Access Reason Logging (The "Gatekeeper")Before a provider can call the GET /api/records/:patientId endpoint, the backend must validate a "Reason Header" or a body parameter.Validation: The API will reject requests that do not include an x-access-reason.Automation: Once the record is successfully served, the backend automatically triggers a "Create Audit Entry" function to log the event permanently.4. Two-Factor Authentication (2FA) WorkflowSince this is a simulation, we will implement a Time-based One-Time Password (TOTP) flow or an Email-based OTP.Step 1: User logs in with password. Backend returns a partial_success status and a temporary 2FA_Token.Step 2: User submits OTP. Backend verifies the OTP against the TwoFactorAuth collection.Step 3: Upon success, the full JWT session is issued.5. Technical Implementation HighlightsTTL (Time-To-Live) Indexes: Use MongoDB’s expiresAt index on the Consent collection. This automatically deletes/expires permissions without needing a manual cron job.Immutability: The AuditLog collection should have no Update or Delete endpoints. It is "Append-Only" to ensure integrity.Middleware Stack: Authenticate -> Authorize(Role) -> VerifyConsent -> LogAccess -> Final Controller.
