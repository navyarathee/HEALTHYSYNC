Phase 1 Frontend Design Doc: Identity & Shell1. Technology StackFramework: React.js (Vite)Styling: Tailwind CSS (for rapid, responsive UI development)State Management: React Context API (to manage User Auth state)Routing: React Router DOMAPI Client: Axios (with interceptors for JWT injection)2. User Interface ArchitectureThe application will use a Layout-based routing system to distinguish between public pages and the protected internal dashboards.Public Layout: Simple, centered containers for Login and Registration.Authenticated Layout: A sidebar-navigation structure with a top header containing the user's name and role.3. Core Components & ViewsA. Authentication ModuleLogin Page: A clean form with email/password fields. It must handle the JWT response and store it in localStorage or a Secure Cookie.Register Page: A multi-step form or a simple toggle to choose a role (Patient or Provider).Note: The form fields should change based on the role (e.g., Patients enter blood group; Providers enter medical license/ID).B. The "Shell" (Main Dashboard)Sidebar Navigation: Role-aware links.Patients see: Profile, My Records, Appointments.Providers see: Patient Lookup, My Schedule, Collaboration.Stat Cards: Top-level summary data (e.g., "Last Login," "Recent Records," or "Upcoming Visits").4. Patient Profile & Record Module (MVP)This is where the user interacts with the CRUD logic you built in the backend Phase 1.Profile View: A read-only "Health Card" displaying allergies, chronic conditions, and emergency contacts, with an "Edit" toggle.Record List: A simple table or grid view showing the title, category, and date of uploaded documents.Upload Modal: A form using an <input type="file"> that sends multipart/form-data to your /api/records endpoint.5. Frontend-to-Backend Integration LogicAuth Interceptor: An Axios interceptor that automatically attaches the Authorization: Bearer <token> header to every request if a token exists.Protected Routes: A higher-order component (HOC) that redirects unauthenticated users to /login and unauthorized roles (e.g., a Patient trying to access the Provider Lookup) to a 403 Forbidden page.6. Phase 1 User FlowLand on Login: User enters credentials.Redirect: User is sent to /dashboard based on their role.Fetch Data: Dashboard makes a GET /api/users/me call to populate the UI.Action: Patient clicks "Upload Record," selects a PDF, and sees the list update in real-time.📊 Phase 1 Screen InventoryRouteView NamePrimary Function/loginLogin ScreenAuthenticate User/registerSignup ScreenCreate Account (Role Selection)/dashboardMain ShellRole-based navigation & Stats/profilePatient ProfileView/Update Medical Metadata/recordsRecord ManagerList & Upload Medical Files
