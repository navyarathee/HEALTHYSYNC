Phase 4 Design Doc: Clinical Security & SyncGoal: Implement the "Heart" of HealthSync—Consent, Auditing, and Collaboration (Week 4 & 5 Goals).1. The Consent Enforcement EngineThis is the middleware that sits between your API routes and your Controllers to ensure privacy.Logic: A custom middleware verifyConsent that intercepts requests.Self-Access: If req.user.id === patientId, allow.Provider Access: The middleware queries the Consents collection for a record where providerId === req.user.id AND status === 'active' AND expiresAt > Date.now().Emergency Override: A special flag in the request header (x-emergency-access: true) can bypass the check, but it must trigger a "Critical" Audit Log entry.2. Access Reason & Audit LoggingAccess Reason: Modify your Medical Record retrieval API to require a reason field (e.g., "Consultation", "Emergency", "Follow-up"). If missing, the request returns 400 Bad Request.Audit Collection Schema:timestamp: Date.now()actorId: ID of the person accessing the data.patientId: ID of the patient whose data was accessed.action: (e.g., "RECORD_VIEW", "CONSENT_GRANT", "LOGIN").reason: The justification provided by the doctor.ipAddress: For security tracking.Integrity Rule: This collection is Append-Only. There are no Update or Delete routes for Audit Logs.3. Multi-Provider Collaboration (Week 5)This allows the "Team-based Care" model where multiple specialists can discuss a patient.Collaboration Note Schema:patientId: The subject of the discussion.authorId: The provider writing the note.content: The clinical observation.visibility: (e.g., "Internal" or "Shared with Patient").Access Rule: Only providers who have active consent for that patient can view the "Case Discussion" thread.4.
